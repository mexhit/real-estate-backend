# Second Gemini AI Provider is a parameterized instance, not a duplicate class, and shares model/retry config with the primary

Adding a second Gemini AI Provider (`GEMINI_2`) for a separate API key could have followed the existing pattern where each AI Provider is its own class (`GeminiAiProviderService`, `GroqAiProviderService`). Instead, `GeminiAiProviderService` takes its config (API key, model, max retries, retry delay) via constructor, and `properties.module.ts` registers it twice through DI factory tokens with different API keys — avoiding a near-identical duplicate class for a one-off second account. The two instances also intentionally share the same `GEMINI_MODEL`/`GEMINI_MAX_RETRIES`/`GEMINI_RETRY_DELAY_MS` env vars; only the API key differs. This was a deliberate scope call for now (see the AI Provider entry in CONTEXT.md) — if `GEMINI_2` later needs its own model or retry behavior, add `GEMINI_2_MODEL`/etc. env vars and thread them through the same factory, rather than reaching for a duplicate class.
